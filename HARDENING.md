## Findings Fixed

### script-injection (severity: high)

Rule (a): the composite step's pwsh run: block puts the GitHub expression `${{ runner.os }}` straight into the script text: `if ('${{ runner.os }}' -ne 'Windows') {` and `echo 'Not going to set up a Visual Studio shell on ${{ runner.os }}'`. Any ${{ }} inside a run: block is a finding. Use $env:RUNNER_OS instead. A second problem in the same step: the input-derived $Arch (from inputs.arch via ARG_ARCH) is built into a command string for `& "${env:COMSPEC}" /s /c "...-arch=$Arch -no_logo && pwsh ..."`. cmd.exe parses that string again, so metacharacters such as & or | in the input would run extra commands. Check $Arch against an allowlist (for example x86, x64, arm64, amd64) before using it.

### github-env-injection (severity: high)

The step writes every process environment variable to $GITHUB_ENV with no sanitization: `Get-ChildItem env: | %{ echo "$($_.Name)=$($_.Value)" >> $env:GITHUB_ENV }`. That includes ARG_ARCH (from inputs.arch) and any env var inherited from the calling workflow. A value containing a newline (CR/LF) can add arbitrary entries to GITHUB_ENV, such as LD_PRELOAD, NODE_OPTIONS or PATH. Strip \r and \n from each value before writing it (e.g. `$_.Value -replace "[\r\n]",""`), or write it in heredoc form with a delimiter generated by [guid]::NewGuid().
